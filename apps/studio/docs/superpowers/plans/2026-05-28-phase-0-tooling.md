# Phase 0: Tooling Migration (pip + venv → uv + ruff) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `pip + requirements.txt + venv` with `uv + pyproject.toml`, add `ruff` for linting, with zero changes to business code or test outcomes (38 tests must still pass).

**Architecture:** Tooling-only change. No app code modifications. `pyproject.toml` becomes the single source of truth for dependencies, build config, ruff rules, and pytest config. `uv.lock` provides reproducible installs. `ruff` is added with a conservative lint rule set (`F`, `E`, `I`); auto-format is **not** run (avoids massive unrelated diffs).

**Tech Stack:** uv (package manager) + ruff (linter) + Python 3.11+ (existing).

**Spec:** `docs/superpowers/specs/2026-05-28-optimize-existing-design.md` — Phase 0 section.

- [ ] **Step 2: Create pyproject.toml**

Write `pyproject.toml` with the exact content:

```toml
[project]
name = "geelark-studio"
version = "0.1.0"
description = "Self-contained web application for managing TikTok accounts via GeeLark cloud-phone API"
requires-python = ">=3.11"
dependencies = [
    "fastapi>=0.115.0",
    "uvicorn[standard]>=0.30.0",
    "APScheduler>=3.10.0",
    "python-multipart>=0.0.9",
    "python-dotenv>=1.0.0",
    "requests>=2.31.0",
    "google-genai>=1.0.0",
    "httpx>=0.27.0",
    "itsdangerous>=2.0.0",
    "gdown>=5.2.0",
]

[dependency-groups]
dev = [
    "pytest>=8.0.0",
    "ruff>=0.6.0",
]

[tool.uv]
package = false  # this is an app, not a library

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
# Conservative baseline: pyflakes (F) + pycodestyle errors (E) + import sorting (I).
# Expand rule sets in future PRs once baseline is clean.
select = ["F", "E", "I"]
ignore = []

[tool.pytest.ini_options]
testpaths = ["tests"]
filterwarnings = ["ignore::DeprecationWarning"]
```

Notes on the choices:
- `package = false` — uv treats this as an app, not a library (skips build wheel attempts).
- `dev` group holds pytest + ruff. `uv sync` installs the dev group by default; `uv sync --no-dev` skips it for production-only installs.
- Dependency versions copied verbatim from `requirements.txt` — do **not** bump versions in this task.
- `pytest.ini_options` mirrors current `pytest.ini` exactly.
- `ruff line-length=100` is conservative; we don't run `ruff format` in this phase, so this only affects future lint warnings.

```bash

```

Capture: total error count and a breakdown by rule code. Example output:
```

...

```

- [ ] **Step 2: Decide cleanup scope based on count**

**Decision rule:**
- **< 20 errors:** Fix them in this commit. Run `uv run ruff check --fix app/ tests/ ...` for `--fix`-able rules (mostly `I001` import sorting). Manually fix any remaining.
- **20–50 errors:** Same as above — likely 90% import sorting auto-fixable, the rest a small manual cleanup.
- **> 50 errors:** Do **not** mass-fix in this PR. Instead, add `ignore` rules in `[tool.ruff.lint]` to silence the dominant noise (e.g., `ignore = ["E501"]` for line-length, or per-file-ignores). Goal: ratchet baseline to zero errors *without* touching business code. Cleanup happens in follow-up PRs.

Record which path you took in the commit message.
